# TaskApp — مدیریت تسک شخصی با تم گیمینگ

> این فایل مرجع کامل پروژه است: هدف، منطق، معماری، جریان داده، ظاهر مدنظر و راهنمای توسعه.
> هم برای برنامه‌نویسی که می‌خواهد روی پروژه کار کند نوشته شده و هم برای هوش مصنوعی (AI) که باید بدون دیدن بقیه‌ی مکالمه‌ها پروژه را بفهمد و تغییر بدهد.

---

## ۱. پروژه برای چیست؟

یک برنامه‌ی **لوکال و تک‌کاربره** برای نوشتن و پیگیری تسک‌های شخصی که روی ویندوز اجرا می‌شود (با پایتون یا به‌صورت `TaskApp.exe`) و در مرورگر باز می‌شود.

### خواسته‌های اصلی صاحب پروژه

1. فقط تسک بنویسم و وقتی انجام شد تیک بزنم.
2. **زمان‌بندی اجباری نیست.** تسک یک‌هفته‌ای ممکن است در یک روز تمام شود و برعکس. پس تسک‌ها به بازه‌ی زمانی ثابت قفل نمی‌شوند، مگر تسک‌های تکراری که خودش خواسته.
3. یک تسک می‌تواند **زیرتسک** داشته باشد (مثلاً ۴ زیرتسک) و پیشرفتش دیده شود.
4. **گزارش‌گیری:** چه کارهایی این هفته / ماه / فصل انجام شده.
5. **حتماً فارسی و راست‌چین**، و اضافه شدن متن انگلیسی وسط متن فارسی نباید چیدمان را بهم بریزد.
6. **ظاهر گیمینگ:** کارت به‌جای ردیف، دکمه‌های نئونی، حالت شب/روز، منوی سمت راست، سیستم سطح و XP.
7. **آنلاین/آفلاین:** با اینترنت از CDN (Bootstrap، آیکون، فونت) و بدون اینترنت از فایل‌های محلی.
8. معماری قابل توسعه؛ ظاهر جدا از منطق تا بعداً بشود عکس PNG و افکت اضافه کرد.
9. چهار نوع تسک (بخش ۴).

## ۲. تکنولوژی

| بخش | انتخاب |
|---|---|
| زبان / بک‌اند | Python 3 + Flask 3 (Application Factory + Blueprint) |
| دیتابیس | SQLite با ماژول داخلی `sqlite3` (بدون ORM، SQL خام) |
| قالب | Jinja2 (سمت سرور، بدون SPA) |
| ظاهر | Bootstrap 5.3 RTL + Bootstrap Icons + فونت Vazirmatn + CSS اختصاصی |
| جاوااسکریپت | Vanilla JS (بدون فریم‌ورک) |
| خروجی exe | PyInstaller (`--onefile`) |
| محیط توسعه | ویندوز + VS Code + venv |

**اصل مهم:** همه‌ی فرم‌ها `POST` معمولی هستند و بعدش `redirect` (الگوی Post/Redirect/Get). هیچ API/AJAX ای فعلاً وجود ندارد.

## ۴. منطق کسب‌وکار

### ۴.۱ چهار نوع تسک (`tasks.kind`)

| kind | نام | رفتار |
|---|---|---|
| `daily` | روزانه | هر روز باید انجام شود. هر روز بدون تیک شروع می‌شود. |
| `weekly` | هفتگی | فقط در روزهای انتخاب‌شده‌ی هفته نمایش داده می‌شود (مثلاً ۳ بار در هفته، روزهای زوج یا فرد). |
| `project` | پروژه | متعلق به یک پروژه (مثلاً «ربات تلگرام»). با پیشرفت کار تسک جدید داخلش اضافه می‌شود. |
| `random` | رندم | تسک معمولی بدون زمان‌بندی. |

ثابت‌ها در `services.py`: `KINDS`, `RECURRING = ("daily", "weekly")`.

### ۴.۲ تسک تکراری در مقابل تکی

- **تکراری (`daily`, `weekly`):** خودِ ردیف `tasks` هیچ‌وقت `is_done=1` نمی‌شود. انجام‌شدن هر روز در جدول `task_logs` با تاریخ همان روز ثبت می‌شود. با این کار هر روز دوباره تیک‌نخورده شروع می‌شود و تاریخچه‌ی دقیق برای گزارش می‌ماند.
- **تکی (`project`, `random`):** با `is_done` و `completed_at` روی خود ردیف کار می‌کند.
- **زیرتسک فقط برای تکی‌ها** (پروژه/رندم) مجاز است، چون تسک تکراری هر روز ریست می‌شود. `add_subtask` برای تکراری‌ها هیچ کاری نمی‌کند.

### ۴.۳ هفته‌ی ایرانی

- **شنبه = روز ۰ ... جمعه = روز ۶.**
- تبدیل از پایتون (دوشنبه=۰ ... یکشنبه=۶): `persian_weekday(d) = (d.weekday() + 2) % 7`.
- روزهای انتخاب‌شده‌ی تسک هفتگی در ستون `weekdays` به‌صورت متن ذخیره می‌شود: `"0,2,4"`.
- میان‌بر **فرد** = شنبه، دوشنبه، چهارشنبه = `[0,2,4]` و **زوج** = یکشنبه، سه‌شنبه، پنجشنبه = `[1,3,5]` (ثابت‌های `ODD_DAYS`, `EVEN_DAYS`). کاربر می‌تواند هر ترکیب دلخواهی هم تیک بزند.
- `is_due(task, date)` تعیین می‌کند تسک تکراری برای آن روز نوبتش هست یا نه.
- هنوز تاریخ **شمسی** استفاده نمی‌شود؛ تاریخ‌ها میلادی ISO هستند. فقط نام روزها فارسی/ایرانی است.

### ۴.۴ پروژه

- جدول `projects` + `tasks.project_id`. حذف پروژه، تسک‌هایش را هم حذف می‌کند (`ON DELETE CASCADE`).
- پیشرفت پروژه = تسک‌های انجام‌شده ÷ کل تسک‌های پروژه.
- ساخت پروژه ← ورود به صفحه‌ی جزئیات ← نوشتن مرحله‌ها به‌مرور.
- ستون `is_archived` آماده‌ی آرشیو است ولی هنوز دکمه‌اش در UI نیست.

### ۴.۵ پیشرفت کارت (`pct`)

- تکراری: امروز انجام شده ⇒ ۱۰۰ وگرنه ۰.
- تکی با زیرتسک: `done_count / total`.
- تکی بدون زیرتسک: ۱۰۰ اگر انجام‌شده وگرنه ۰.
- تسک اصلی دستی تیک می‌خورد، حتی اگر زیرتسک‌ها کامل نباشند (خواسته‌ی کاربر: «تیک خورد ولی ۴ زیرتسک داشت و همه را ببینم»).
- اگر به تسک تیک‌خورده زیرتسک جدید اضافه شود، تسک **دوباره باز** می‌شود (`is_done=0`).

### ۴.۶ XP، سطح و استریک (`compute_stats`)

```
xp     = (تسک تکی انجام‌شده + تعداد لاگ روتین‌ها) × 10  +  زیرتسک انجام‌شده × 3
level  = xp // 100 + 1
xp_in_level = xp % 100
```

- **استریک:** تعداد روزهای پشت‌سرهم که حداقل یک کار انجام شده (از `task_logs.done_date` و `substr(completed_at,1,10)` تسک‌های تکی). اگر امروز هنوز کاری نشده، از دیروز شمرده می‌شود تا استریک نیمه‌روز صفر نشود.
- شمارنده‌ی «امروز X/Y» = روتین‌های امروز انجام‌شده / روتین‌هایی که امروز نوبتشان است.
- ضرایب XP (۱۰ و ۳ و ۱۰۰) فقط در `services.compute_stats` هستند.
- XP با حذف تسک یا لغو تیک کم می‌شود (از روی داده‌ها محاسبه می‌شود، جدا ذخیره نمی‌شود).

### ۴.۷ گزارش‌گیری (`routes/reports.py`)

بازه‌ها (`PERIODS`):

| کلید | بازه |
|---|---|
| `today` | از امروز |
| `week` | از شنبه‌ی همین هفته |
| `month` | ۳۰ روز اخیر |
| `season` | ۹۰ روز اخیر (تقریب فصل) |

سه بخش خروجی: **روتین‌ها** (هر روتین چند بار انجام شده + آخرین بار)، **تسک‌های پروژه/رندم انجام‌شده**، **زیرتسک‌های انجام‌شده**.
فصل واقعی شمسی هنوز پیاده نشده.

## ۵. دیتابیس

فایل `tasks.db` کنار پروژه (یا کنار exe) ساخته می‌شود (`get_data_dir()` در `app/__init__.py`).

```
projects                tasks                        subtasks
─────────               ─────────                    ─────────
id PK                   id PK                        id PK
name                    title                        task_id FK → tasks (CASCADE)
is_archived             kind  (daily|weekly|         title
created_at                     project|random)       is_done
                        weekdays "0,2,4"             completed_at
                        project_id FK → projects
                        is_done                  task_logs
                        created_at               ─────────
                        completed_at             id PK
                                                 task_id FK → tasks (CASCADE)
                                                 done_date  "YYYY-MM-DD"
                                                 UNIQUE(task_id, done_date)
```

- `PRAGMA foreign_keys = ON` در هر اتصال (برای CASCADE ضروری است).
- تاریخ‌ها: `datetime('now','localtime')` به‌صورت متن `YYYY-MM-DD HH:MM:SS`. مقایسه‌ی رشته‌ای برای بازه‌ها درست کار می‌کند.
- **Migration:** `db._migrate()` ستون‌های `kind`, `weekdays`, `project_id` را اگر در دیتابیس قدیمی نبودند با `ALTER TABLE` اضافه می‌کند. تسک‌های قدیمی `random` می‌شوند.
- برای تغییر ساختار: هم `schema.sql` را عوض کن (برای دیتابیس تازه) هم یک شرط در `_migrate` بنویس (برای دیتابیس‌های موجود). قبلش از `tasks.db` کپی بگیر.

## ۶. جریان داده

### ۶.۱ نمایش یک صفحه (GET)

```
مرورگر  ──GET /──►  routes/tasks.py:index()
                       │ 1. sv.query_tasks(...)        → ردیف‌های tasks (JOIN projects)
                       │ 2. sv.is_due(...)             → فیلتر روتین‌های امروز
                       │ 3. sv.build_items(rows, day)  → دیکشنری آماده‌ی نمایش
                       │ 4. sv.filter_items(items, st) → فیلتر وضعیت + مرتب‌سازی
                       ▼
                 render_template("index.html", ...)
                       │  + context_processor سراسری (app/__init__.py) در همه‌ی صفحات:
                       │      stats = services.compute_stats()   (XP، سطح، استریک، پروژه‌ها)
                       │      WEEKDAYS = نام روزها
                       ▼
           base.html (منو) + index.html + _macros.html:task_card
```

ساختار هر `item` که `build_items` می‌سازد:

```python
{
  "task": <Row>, "recurring": bool,
  "subtasks": [...], "total": int, "done_count": int,
  "pct": int, "done": bool,
  "times": int,        # فقط تکراری: تعداد کل انجام
  "schedule": str      # فقط تکراری: «هر روز» یا «شنبه، دوشنبه»
}
```

### ۶.۲ تغییر داده (POST → Redirect)

```
فرم HTML ──POST /tasks/<id>/toggle──► toggle_task()
     تکراری؟ ──► INSERT/DELETE در task_logs (تاریخ امروز)
     تکی؟    ──► UPDATE tasks SET is_done / completed_at
     db.commit()
     return back()  ──► redirect به request.referrer (فیلتر/صفحه‌ی فعلی حفظ می‌شود)
```

### ۶.۳ جدول مسیرها

| متد | مسیر | تابع | کار |
|---|---|---|---|
| GET | `/` | `tasks.index` | صفحه‌ی امروز (`?status=all|pending|done`) |
| GET | `/routines` | `tasks.routines` | همه‌ی روتین‌ها |
| POST | `/tasks/add` | `tasks.add_task` | افزودن تسک (`kind`, `title`, `weekdays`, `project_id`) |
| POST | `/tasks/<id>/toggle` | `tasks.toggle_task` | تیک |
| POST | `/tasks/<id>/delete` | `tasks.delete_task` | حذف |
| POST | `/tasks/<id>/subtasks/add` | `tasks.add_subtask` | افزودن زیرتسک |
| POST | `/subtasks/<id>/toggle` | `tasks.toggle_subtask` | تیک زیرتسک |
| POST | `/subtasks/<id>/delete` | `tasks.delete_subtask` | حذف زیرتسک |
| GET | `/projects/` | `projects.list_projects` | لیست پروژه‌ها |
| POST | `/projects/add` | `projects.add_project` | ساخت پروژه |
| GET | `/projects/<id>` | `projects.detail` | تسک‌های پروژه |
| POST | `/projects/<id>/delete` | `projects.delete_project` | حذف پروژه |
| GET | `/reports/` | `reports.report` | گزارش (`?period=today|week|month|season`) |

## ۷. ظاهر مدنظر (UI/UX)

### ۷.۱ چیدمان

- **منوی سمت راست** ثابت (`.sidebar`، با `inset-inline-start:0` که در RTL یعنی راست). شامل: برند، کارت بازیکن (سطح، XP، نوار پیشرفت، 🔥 استریک)، لینک‌ها (امروز با شمارنده‌ی `X/Y`، روتین‌ها، پروژه‌ها، گزارش)، لیست پروژه‌های فعال، دکمه‌ی تم.
- در موبایل (زیر ۹۹۲px) منو مخفی است و با دکمه‌ی همبرگری باز می‌شود.
- محتوا به‌صورت **شبکه‌ی کارت** (Bootstrap `row g-4` و ستون‌های `col-12 col-md-6 col-xxl-4`)، نه ردیف.

### ۷.۲ کارت تسک

- شیشه‌ای (`backdrop-filter`)، نوار رنگی بالا، درخشش نئونی روی hover.
- دکمه‌ی تیک گرد؛ با تیک خوردن سبز می‌شود و عنوان خط می‌خورد.
- نوار پیشرفت، بج نوع تسک (روزانه/هفتگی/پروژه/رندم)، زیرتسک‌ها در `<details>` بازشونده، تاریخ ساخت در پایین.
- رنگ بالای کارت: روزانه=فیروزه‌ای→صورتی، هفتگی=صورتی→فیروزه‌ای، پروژه=سبز→فیروزه‌ای، رندم=خنثی، انجام‌شده=سبز.

### ۷.۳ تم و رنگ

- شب (پیش‌فرض) و روز، با `data-bs-theme` روی `<html>`. انتخاب در `localStorage` ذخیره می‌شود و یک اسکریپت کوچک در `<head>` قبل از رندر اعمالش می‌کند (جلوگیری از چشمک).
- **همه‌ی رنگ‌ها فقط در `theme.css`** با متغیر:
  - `--n1` فیروزه‌ای، `--n2` صورتی، `--n3` سبز، `--n4` قرمز (به‌صورت `R, G, B` تا بشود `rgba(var(--n1), .5)` نوشت)
  - `--glow` شدت درخشش (روز کمتر)
  - `--bg-image` برای عکس پس‌زمینه
- دکمه‌ی نئونی `.btn-neon`، نوار XP گرادیانی، چیپ‌های فیلتر.

### ۷.۴ فارسی و راست‌چین (قانون‌های سخت)

1. `<html lang="fa" dir="rtl">` و `html { direction: rtl }`.
2. **هر متن کاربر و هر input:** `dir="auto"` روی تگ + در CSS `unicode-bidi: plaintext; text-align: start;` روی `.task-title`, `input[type=text]`, `.parent`. این‌طوری تسک انگلیسی راست‌به‌چپ بهم نمی‌ریزد و جهت هر تسک از اولین حرفش تشخیص داده می‌شود.
3. تاریخ‌ها `.date` با `direction: ltr; unicode-bidi: isolate`.
4. برای فاصله/چیدمان از ویژگی‌های logical استفاده کن (`margin-inline-start`, `inset-inline-start`) نه `left/right`.
5. هر عنصر جدید که متن کاربر نشان می‌دهد باید `dir="auto"` داشته باشد.

### ۷.۵ آنلاین / آفلاین

در `base.html` هر CSS اول از CDN لود می‌شود و در صورت خطا (`onerror`) خودکار به نسخه‌ی محلی در `static/vendor/` می‌رود. فایل‌های محلی را `download_assets.py` یک بار (با اینترنت) دانلود می‌کند. فونت: Vazirmatn (Google Fonts) و `VazirLocal` محلی در `base.css`، و در نهایت Tahoma.

### ۷.۶ برای زیباسازی بعدی (دست باز)

- عکس پس‌زمینه: فایل را در `static/img/` بگذار و در `theme.css` مقدار `--bg-image: url("../img/bg.png")`.
- آواتار/آیکون PNG: داخل `static/img/` و استفاده در `base.html` یا `_macros.html`.
- رنگ‌ها: فقط متغیرهای `--n1..n4`.
- افکت‌های جدید: در `features.css` یا فایل CSS جدید که در `base.html` لینک می‌شود (بعد از `theme.css`).
- ترتیب لود CSS مهم است: Bootstrap → `base` → `components` → `theme` → `features`.

## ۱۰. قراردادها و تله‌ها (مخصوصاً برای AI)

1. **منطق در `services.py`، نه در template یا route.** Templateها فقط نمایش می‌دهند.
2. **تسک تکراری هرگز `is_done=1` نمی‌شود.** وضعیتش از `task_logs` و تاریخ امروز مشتق می‌شود. کد جدید نباید این را بشکند.
3. همه‌ی SQLها پارامتری (`?`) هستند. هرگز متن کاربر را در SQL فرمت نکن. (فقط `where` داخلی در `query_tasks` با f-string ساخته می‌شود و فقط از کد خود برنامه می‌آید، نه ورودی کاربر.)
4. بعد از هر تغییر داده `db.commit()` و `return back()`.
5. `inject_globals` در `create_app` برای **هر** رندر اجرا می‌شود؛ `compute_stats` باید سبک بماند.
6. نام ماکرو/فایل‌های `_macros.html` با زیرخط شروع می‌شود، یعنی صفحه‌ی مستقل نیست.
7. شماره‌ی روزها شنبه=۰ است؛ هرگز مستقیم از `date.weekday()` پایتون استفاده نکن، از `persian_weekday` استفاده کن.
8. متن UI فارسی است؛ نام متغیرها/توابع/کامنت‌های فنی انگلیسی یا فارسی ساده.
9. `url_for('static', ...)` برای همه‌ی فایل‌های استاتیک (در exe هم کار می‌کند).
10. خطای `'stats' is undefined` یعنی `context_processor` در `create_app` ثبت نشده (فایل `__init__.py` قدیمی است).

## ۱۲. به‌روزرسانی نسخه‌ی ۳: صفحه‌ی انجام‌شده‌ها + دسته‌بندی تسک‌های رندم

> این بخش بر بخش‌های قبلی **ارجحیت دارد**. هرجا با بخش‌های بالا فرق داشت، این بخش درست است.

### قانون جدید: تسک انجام‌شده از صفحه‌های افزودن حذف می‌شود
- صفحه‌ی **امروز** (`/`) و صفحه‌ی **جزئیات پروژه** فقط تسک‌های **انجام‌نشده** را نشان می‌دهند. چون صفحه‌های افزودن‌اند و نباید شلوغ شوند.
- تسک انجام‌شده به صفحه‌ی **انجام‌شده‌ها** (`GET /done`) می‌رود. در این صفحه می‌شود تیک را برداشت (تسک برمی‌گردد) یا حذف کرد.
- محتوای `/done`: روتین‌هایی که **امروز** انجام شده‌اند (از `task_logs`)، تسک‌های رندم انجام‌شده، تسک‌های پروژه‌ی انجام‌شده (مرتب بر اساس `completed_at` نزولی).
- فیلتر: `?kind=all|routine|random|project` و `?project=<id>` (فقط انجام‌شده‌های یک پروژه).
- فیلتر قبلی «همه / در انتظار / انجام‌شده» (`?status=`) و تابع `filter_items` **حذف شدند**.
- نمایش در سرویس: `services.done_routines_today()` و `services.done_oneoff(kind, project_id=None)`.
- شمارنده‌ی منو (`stats.done_total`) = تسک‌های تکی انجام‌شده + لاگ‌های روتین امروز.

### دسته‌بندی تسک‌های رندم
- جدول جدید `categories(id, name, color 1..4, created_at)` و ستون `tasks.category_id` (`ON DELETE SET NULL`، یعنی با حذف دسته تسک‌ها «بدون دسته» می‌شوند، حذف نمی‌شوند).
- فقط تسک‌های `random` دسته می‌گیرند. رنگ دسته خودکار است: `(تعداد دسته‌ها % 4) + 1` که به `--n1..--n4` نگاشت می‌شود.
- در صفحه‌ی امروز تسک‌های رندم **گروه‌گروه** نشان داده می‌شوند (`services.group_by_category`). هر گروه فرم افزودن سریع مخصوص خودش را دارد.
- هر کارت رندم یک `<select>` برای جابه‌جایی دسته دارد.
- فرم اصلی افزودن وقتی نوع «رندم» انتخاب باشد، انتخاب‌گر دسته را نشان می‌دهد (در `app.js`).
- ساخت دسته‌ی جدید: فرم کوچک بالای بخش رندم.

### فایل‌ها و مسیرهای جدید
| مورد | شرح |
|---|---|
| `app/routes/categories.py` | blueprint جدید: `POST /categories/add`، `POST /categories/<id>/delete` |
| `app/templates/done.html` | صفحه‌ی انجام‌شده‌ها |
| `POST /tasks/<id>/category` | تغییر دسته‌ی یک تسک رندم (`tasks.set_category`) |
| `GET /done` | `tasks.done` |
| `services.query_tasks(where, params, order)` | پارامتر `order` اضافه شد و JOIN با `categories` (فیلدهای `category_name`, `category_color`) |
| `_macros.html: task_card(item, cats=[])` | پارامتر دوم برای لیست دسته‌ها (انتخاب‌گر جابه‌جایی) |
| `build_exe.bat` | `--hidden-import app.routes.categories` اضافه شد |

### تله‌ها
- برای دیتابیس قدیمی، ستون `category_id` توسط `db._migrate` اضافه می‌شود. جدول `categories` باید قبل از آن در `schema.sql` باشد.
- در `index.html` فرم‌ها تو در تو نیستند (فرم ساخت دسته جدا از فرم افزودن تسک است). این را نشکن؛ HTML فرم تو در تو را نمی‌پذیرد.
- ماکرو `task_card` ورودی دوم دارد؛ صفحه‌هایی که آن را پاس نمی‌دهند (روتین‌ها، انجام‌شده‌ها، پروژه) انتخاب‌گر دسته را نمی‌بینند و این درست است.

## ۱۳. به‌روزرسانی نسخه‌ی ۴: سیستم تم رنگی ۳رنگه + صفحه‌ی تنظیمات

> این بخش بر بخش‌های قبلی **ارجحیت دارد**.

### ایده
کل ظاهر پروژه از **۳ رنگ** ساخته می‌شود:

| رنگ | نقش | متغیرهای ساخته‌شده |
|---|---|---|
| رنگ ۱ · `bg` | پس‌زمینه | `--bg --bg-2 --card --side --text --muted --border --input` |
| رنگ ۲ · `main` | اصلی | `--n2` (گرادیان، برچسب، سطح کارت) |
| رنگ ۳ · `accent` | تأکیدی | `--n1` (دکمه، لینک فعال، نئون) |

`--n3` (سبز، «انجام شد») و `--n4` (قرمز، «حذف») **ثابت و معنایی** هستند و جزو ۳ رنگ نیستند.

### جریان داده
```
جدول themes (دیتابیس)  ──►  themes.get_active_theme()  ──►  context_processor (متغیر theme)
   ──►  base.html:  window.APP_THEME = {{ theme|tojson }}
   ──►  static/js/theme-engine.js  (ThemeEngine.boot)  ──►  متغیرهای CSS روی <html>
   ──►  theme.css / features.css / settings.css  (فقط از var(...) استفاده می‌کنند)
```
- **موتور تم** (`theme-engine.js`) تنها جایی است که رنگ‌ها محاسبه می‌شوند. هم برای کل سایت و هم برای «نمونه‌ی زنده» در تنظیمات استفاده می‌شود (`ThemeEngine.apply(element, colors, mode)`).
- قبل از رندر اجرا می‌شود (داخل `<head>`)، پس صفحه چشمک نمی‌زند.
- **قانون:** توی CSS هیچ رنگ ثابتی ننویس. رنگ کامل `var(--text)`، با شفافیت `rgba(var(--n1), .5)`، متن روی سطح رنگی `var(--on-n1)` / `var(--on-n3)` / `var(--on-grad)`. مقادیر داخل `:root` در `theme.css` فقط پشتیبان‌اند.

### شب/روز
- هر پالت یک «حالت طبیعی» دارد (پس‌زمینه‌ی تیره = شب، روشن = روز).
- دکمه‌ی شب/روز نسخه‌ی مقابل همان پالت را نشان می‌دهد (پس‌زمینه وارونه می‌شود: `mix(bg, white, .93)` یا `mix(bg, black, .90)`).
- وقتی تم عوض شود، حالت دوباره روی حالت طبیعی پالت می‌رود (کلیدهای localStorage: `tm_mode` و `tm_sig`؛ کلید قدیمی `theme` دیگر استفاده نمی‌شود).
- **محافظ خوانایی:** اگر رنگ اصلی/تأکیدی روی پس‌زمینه کنتراست کمتر از ۳ داشته باشد، خودکار کمی تیره/روشن‌تر می‌شود (مثلاً سفید روی صورتی). `--on-*` رنگ متن روی سطح پرشده را با کنتراست بهتر انتخاب می‌کند.

### تم‌های پیش‌فرض (در `themes.PRESETS`، هر بار اجرا با دیتابیس هماهنگ می‌شوند)
1. مشکی، بنفش، فیروزه‌ای (`#07070d  #a855f7  #00e5ff`) ← تم پیش‌فرض
2. سفید، خاکستری، آبی یخی (`#f8fafc  #6b7280  #8fd3ff`)
3. سرمه‌ای، سبزآبی، سفید (`#0b1f3a  #14b8a6  #ffffff`)
4. صورتی پاستلی، سفید، لاوندر (`#ffd9e8  #ffffff  #b79cf2`)

### دیتابیس (جدول‌های جدید)
```
themes:   id, slug (فقط پیش‌فرض‌ها؛ برای کاستوم NULL), name, c_bg, c_main, c_accent (همه HEX), is_builtin, created_at
settings: key, value        # فعلاً فقط active_theme_id
```
تم کاستوم با HEX استاندارد (`#rrggbb`) ذخیره می‌شود. سقف ۳۰ تم کاستوم (`MAX_CUSTOM`). حذف تم فعال، پیش‌فرض را فعال می‌کند. اگر `active_theme_id` خراب باشد، هنگام اجرا خودکار ترمیم می‌شود.

### صفحه‌ی تنظیمات (`/settings/`)
- لینک «تنظیمات» زیر دکمه‌ی شب/روز در منوی راست.
- **تب ۱ · تم رنگی:** لیست تم‌ها (اعمال، ویرایش=آوردن رنگ‌ها به ویرایشگر، حذف کاستوم)، ویرایشگر ۳ رنگ و نمونه‌ی زنده.
- هر رنگ سه ورودی هماهنگ دارد: **انتخاب‌گر رنگ**، **HEX** (با/بدون `#`، سه‌رقمی هم) و **RGB** (`168, 85, 247`). سرور هر دو فرمت را نرمال می‌کند (`themes.normalize_color`).
- **تب ۲ · راهنما.** برای افزودن تب جدید: یک دکمه‌ی `.set-tab[data-tab="x"]` و یک `<section class="set-panel" id="tab-x">` اضافه کن.

### مسیرها
| متد | مسیر | کار |
|---|---|---|
| GET | `/settings/` | صفحه‌ی تنظیمات (`?msg=` برای پیام) |
| POST | `/settings/theme/<id>/apply` | اعمال تم |
| POST | `/settings/theme/save` | ساخت تم کاستوم (`name, c_bg, c_main, c_accent`) و اعمال فوری |
| POST | `/settings/theme/<id>/delete` | حذف تم کاستوم |

### فایل‌های جدید
`app/themes.py` ، `app/routes/settings.py` ، `app/templates/settings.html` ، `app/static/css/settings.css` ، `app/static/js/theme-engine.js` ، `app/static/js/settings.js`
(در `build_exe.bat`: `--hidden-import app.themes` و `app.routes.settings`)

### تله‌ها
- متغیرهای رنگی را فقط موتور تم می‌سازد؛ مقدار دستی در `theme.css` تأثیری ندارد (بالای آن را override می‌کند).
- ترتیب اسکریپت‌ها در `<head>`: داده‌ی `APP_THEME` ← `theme-engine.js` ← `ThemeEngine.boot`. جابه‌جایی‌اش باعث چشمک می‌شود.
- `data-bs-theme` را موتور تم ست می‌کند؛ دستی ست نکن.
